# 为什么我选择原生 JS 构建个人网站

> 2026-04-15

最近很多朋友问我，为什么要用"裸写"的方式建站，而不是直接用 Next.js 或者 Astro。这篇文章聊聊我的思考。

## 框架不是免费的

每个框架都有其代价。React 的运行时体积、Next.js 的服务端复杂度、构建工具链的维护成本——这些在大型项目中是值得的投入，但对于一个个人网站来说，它们往往是过度设计。

一个个人网站的核心需求是什么？

1. 展示内容和作品
2. 提供一个联系渠道
3. 加载快，体验好

这三个需求，原生技术完全能够满足，而且做得更好。

## 速度的真相

我用 Performance 面板测试了几个方案：

| 方案 | FCP | LCP | JS 体积 |
|------|-----|-----|---------|
| Next.js (默认) | 1.8s | 2.4s | ~87KB |
| Astro | 0.9s | 1.2s | ~12KB |
| 原生 HTML | 0.3s | 0.5s | ~5KB |

对于一个内容型网站，原生的性能优势是压倒性的。

## 可维护性又如何？

很多人担心原生代码难以维护。但实际上，对于一个单页个人网站：

- CSS 变量已经覆盖了 90% 的主题需求
- 现代 JavaScript 的模块化和 API 足够强大
- 代码量小意味着出 bug 的概率低
- 没有依赖意味着不会遇到"某个包更新后项目跑不起来"的问题

## 最后的想法

我不是在说框架不好。在合适的场景下，它们是无价的工具。但对于一个个人网站这个具体场景，原生技术提供了最简单的方案、最好的性能、以及最长的保质期。

五年后你还能打开这个网站吗？对于原生 HTML，答案是肯定的。对于需要特定版本 Node.js 和一堆依赖的框架项目，就不一定了。

选择简单的方案，往往就是选择长期的方案。
